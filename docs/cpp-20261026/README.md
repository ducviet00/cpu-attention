# C++ continuation — raw evidence

These are **checkpoint measurements**, not a claim that the acceptance target
has been reached. `SCORECARD.md` is generated by `scripts/cpp_scorecard.py` from
the JSON here; it rejects an incomplete matrix, a missing baseline/control,
or fewer than 41 raw samples per arm.

Hardware is named explicitly: Google Axion is **Neoverse-V2**, not Graviton 5
(Neoverse-V3); GCP C4 is **Xeon Platinum 8581C**, not the AWS 6975P-C. The pinned
vLLM source is `db3b0f0fae4bc98492b3863685e541e62bc59576`. Xeon bf16 uses its
AMX build, Xeon fp32 and Ryzen use VEC, and Axion uses NEON.

The initial checkpoint is the merged tree at `4713aa7`. Ryzen paged was timed
before the final Python plan-key optimization, but after the strict fp32 dot
fix and output-allocation correction. Both backends allocate their paged output;
vLLM retains the audit's preallocated output convention. Ryzen paged uses 41
rotated rounds of 40-call blocks with the performance governor restored on exit.
All other rows use 41 rotated, interleaved single-call rounds. `ctrl` repeats C++.

The first C4 was spot-preempted after its results were copied here. A replacement
spot C4 is used for subsequent experiments; comparisons between candidates are
always in the same process on one VM, never across the two instances.

No measured losing experiment is retained in the production kernel. The
falsification ledger and test results are in `../CPP_REPORT.md`.
